# 税务问题分析引擎 (Tax Analysis Engine)

> **核心原则：先分析，后检索；先定依据，后下结论。永远不凭训练数据直接给出税收政策答案。**

本文件是操作主线，只保留"照着能跑"的那一层判据。每一节的命令全文、参数、
层级表、映射表、源缺陷登记表与评测细则都在 `references/`，需要展开时按指针去读，
不在此复述。

## 工作流程（必须严格遵循）

```
用户提问 → ① 分析判定（问题类型 + 缺失前提，不联网，纯判定） → ② 前提补齐（缺关键前提先问，不猜）
    ↓
③ 层级下挖 ＝ ④ 多源聚合 → 同一趟检索的两根轴：层级按效力深浅（L1 上位法 → L2 规章公告
    → L3 地方口径 → L4 实务案例），源按数据渠道；一趟走完，不分成两道工序各跑一遍
    ↓
⑧ 依据定级 → 三根轴各判各的 + 角色分层，先于作答定出主依据；收口：没取到任何一条未废止的
    "本题的直接规定／上位依据与授权"就不进 ⑥，转 `output_templates.md`「依据不足时」出口
    ↓
⑥ 分层作答 → 结论 + 主依据 + 限制条件 + 待定夺处 + 时间戳 / 观察时点 / 免责声明
```

上面的圈码就是正文各节的节号（①–⑬），全文只有这一套编号，没有第二套；③ 与 ④ 是同一次检索的两根轴（深浅 ×
渠道），不是先后两步；定级（⑧）在排版上排在 ⑥⑦ 之后、执行上却先于作答——读主线按这张顺序图走，别按小节上下顺序当成时序。

判型顺带报出一种六个税收源都答不了的缺口：题面把会计确认与计量写进要件（`tax_analyze.accounting_gap`，
输出叫【会计口径缺口】）；审计/内控/评估/证券口径的原文不受词表触发、按题面直接判——两类都走 ③ 末那两个子技能。

## ① 分析判定：问题类型

同一税种下，不同问题要的依据完全不同。判错型，检索命中再高也没用。

| 类型 | 问法特征 | 关键在于 | 必需依据 |
|-----|---------|---------|---------|
| **entitlement** 优惠资格判定 | 给一组事实问能不能享受 | 逐条过条件，指出卡在哪条 | 优惠本体法 + 条件 + 时限 |
| **liability** 税负测算 | 给业务数据算应纳多少 | 每一步算式要能复核 | 计税依据 + 减免加计 + 起征点 |
| **option_judge** 选项判断 | 下列…正确的有 / 不属于…的有 | **逐条**比对，漏一条就错 | 该法完整条文全文 |
| **fill_blank** 术语填空 | 句中留空，填术语或数值 | 定位到"哪一部法哪一条" | 该法定义条款全文 |
| **procedure** 办理流程 | 怎么办、多久内、找谁办 | 时限是硬约束 | 征管法 + 操作口径 |
| **risk** 风险判断 | 会不会被查、什么后果 | 定性 + 后果区间 + 整改 | 定性法条 + 罚则 + 稽查口径 |
| **treatment** 事项定性 | 该按什么税目、算不算视同销售 | 定性结论 + 援引条款 | 税目定义 + 列举 |
| **compare** 方案比较 | 哪个更划算、怎么选 | 临界条件比结论更重要 | 各方案依据 + 临界值 |
| **lookup** 政策查询 | 规定是什么、最新怎么改 | 要层级、文号与时效 | 现行有效法条 |

判型有两类形态不能靠主题词认，必须靠句式：`（ ）` 前是「包括/有/属于」这类集合动词 → `option_judge`；
`（ ）` 前是术语位置且题里没有「下列/以下」 → `fill_blank`。**内容与形态有主从**：词表命中决定检索什么依据，
题面形态只在词表一个信号都没抓到时才决定胜负（`tax_analyze.classify` 的 `if is_fill_blank and not scores`）。
`confidence=0.30` 是判型层唯一的失焦出口——看到它必须自己重判题面，不能照 `lookup` 清单走。主从关系、
两个可验算指标与实测数字在 `references/classification.md`；`liability`／`entitlement`／`compare` 三类的结论
会被「同一事实官方怎么处理过」改变，题面涉及程序争议、追缴、资格类比时 ⑥ 前追加 `scripts/tax_cases.py`，
争点写法见 `references/classification.md`「哪几类题要追加类案检索」。

```bash
python scripts/tax_analyze.py "<用户原话>"                # 判定结果与理由
python tests/probe_classify.py --stats --real --oracle    # 判型体检（离线）
```

## ② 前提补齐：四根轴

| 轴 | 为什么会改结论 | 题面识别信号 |
|---|---|---|
| **时点** | 政策有生效与失效日期，跨年适用不同版本 | 今年/去年/明年/X年X月/汇算清缴 |
| **主体与身份** | 小规模与一般纳税人、居民与非居民税率和优惠完全不同 | 小规模/一般纳税人/居民/非居民 |
| **地区** | 地方税源、附加税种、扶持政策由省级以下政府定 | X省/X市/注册地/经营地 |
| **金额与规模** | 大量优惠带规模门槛，差一点也不适用 | 万元/销售额/利润/人数/资产 |

处理规则：**先分题型再决定问不问**。`lookup` 与 `fill_blank` 答的是规则本身写了什么，个案三轴不改变规定内容，
不按个案三轴追问（时点轴仍要问），个案缺失由程序转成 `rule_note` 写进【适用边界】；其余题型结论真的随个案变。

该问哪几根轴、该有哪些依据逐项登记在 `data/evidence_requirements.json`；`python scripts/tax_coverage.py <题型>
 --question "<用户原话>"` 把要件、前提轴、展开算式各判成 已满足／缺／不适用／待核，缺的那几项直接回吐
`CONTEXT_AXES` 里现成的追问句；要件名逐字取自 `QUESTION_TYPES[题型]["needs"]`，对不上时 `tax_coverage.load()`
报错而不是少判一项。

**缺轴的处置是收取证范围，不是把每一类都取一遍**：时点没给就先按观察时点现行有效那一版取，
并写明换一个时点这条结论要重看；范围按题面点名项收，收窄排在发检索之前。
`tax_coverage.py` 判出的"缺"是还没检到的层，不是"这些层本轮都必须检"的许可。

**四轴之外还有第三种输入：题面自相矛盾**。同一段话里既写本企业已登记为一般纳税人、
又要求按小规模纳税人的免税起征点来判断时，**先指出冲突并询问，不得择一采用**——
猜前提是把猜测写成答案，择一采用是把"回避矛盾"写成事实，两者都会让用户照着错的那
一半去办。**判断单元按交易拆开**：判断单元是「主体 × 具体应税交易 × 业务所属期 ×
资格条件」，同一主体的不同交易不得并成一个单元（一笔业务里免税项与应税项混在一处，
合并判断会把不能叠加的东西算成可叠加），`liability` 与 `entitlement` 逐笔交易分别给
结论，不能只按主体出一个笼统答案。企业交来结构化账套行（科目＋金额那一类）时，行上缺
哪一格、哪些行没落进比对范围，由 `scripts/tax_ledger.py` 逐行列出来，② 这一层不拿题面
推断账上的数。交来的是合同而不是账时，五件套里的『触发时点』由 `scripts/tax_intake.py`
连出处收成一张时点清单交给 ②——付款节点、开票节点、验收节点、扣缴义务发生时间是四个
不同的时点，② 该按哪一个问，看这张清单上有几个节点，本层不判那个时点上政策是什么。

主线每一格动作的归属（脚本 / Agent）与"做错了在本机怎么发现"的对照表，
在 `references/source_defects.md` 的"主线动作归属"一节——改代码前先看那张表。

## ③ 层级下挖：从上位法一路向下（必做）

**越上层的法律条文越严谨精炼也越晦涩。** 一部法律只给原则和要件，能落到用户情形上的口径在下层的实施条例、
公告、办税指南与实务案例里；每层的具体命令、翻页与缓存参数、NPC 串行闸在 `references/commands.md`，L1/L2 那
三站自己的取数机制——翻页基准为什么两站相反、收窄给越界值为什么回 0 条、清单层与正文层为什么各装一半——在
`search_source/chinatax/`、`search_source/npc-flk/` 与 `search_source/fgk/`。

【⑦ 第 2 条正文】**禁止只查上位法就作答**：必须完成 ③ 的 L1→L3 逐层下挖，资格认定、
计算标准、风险定性、争议类问题必须走到 L4。

- **L1 上位法**：命中税种本体法（法律/行政法规）。**本体法名已知时必须走精确检索（`--exact`）**，
  模糊检索按发布时间排会把「企业所得税」首条带回企业破产法；不要拿用户原话当检索词，先用
  `resolve_tax_type` 归到税种再按 ⑨ 选词。
- **L2 规章与公告**：总局配套公告给优惠条件、比例、时限。**必须翻页**——只读第 1 页会把「库里没有」
  错报成「确实没有」（逐页参数与值域见 `search_source/chinatax/`）。**要的是「整栏横截面」时改用清单源**
  （`scripts/tax_gov_list.py`，先 `sync --channel 栏名` 建索引再离线查；它不在 ④ 的六源里，按词召回
  的开放集合凑不出封闭清单，取回条目回 ⑧ 按同一根轴定级）。
- **L3 地方口径**：省局与地方文件只在搜狗手机端站内搜索里，用 `--site <省>.chinatax.gov.cn`；反爬判据
  与预算熔断为什么按 600 秒 4 次设，在 `search_source/sogou/`，命令仍走 ④ 的 `sogou` 源。
- **L4 实务案例与解读（必做）**：税屋 + 公众号取正文，这一层给的是执行口径（角色 `practice`），照常
  进答案并参与论证，但不能顶替被它解读的那份文件当依据（见 ⑧）。四处的取数细节在 `search_source/shui5/`、
  `search_source/wechat/`、`search_source/ctaxnews/`、`search_source/netpaper/`，命令仍走 ④ 的三源与
  `POST /api/paper`。中国税网是报社登载件、④ 默认名单里的第 6 源（源键 `ctax`）：被它登的那份文件
  才是依据，依据链里的 url 要写官方那份；它与同社数字报同一篇稿常用两副标题，聚合会错并（理由见 ⑪）。

**分轮编排**由 `tax_answer.build_plan` 按题型给轮次模板与候选词、按 ⑨ 判出的 `authority` 换源（sta 专题
第 1 轮直接查总局法规库；overseas 查关掉文件类标签的全站层；末轮补查境内相邻专题）。一轮取不回时
放宽到哪一级是 Agent 的判断，放宽链见 ④。

**同一站点的多词检索并成一轮发**（同一条脚本按词循环、逐词回吐命中数与失败原因），不在会话里一词发一次；
**「按词循环」不等于「把几枚词用空格拼成一串」**——站内搜索按整串或任一词处理，两种都不是 AND。同一主机
连续两次 TLS 握手失败后本会话内不再对它发请求（`tax_http.TLS_STREAK_LIMIT`）；限流记录按 `tests/probe_rate_limit.py` 的三字段契约记进 `references/source_defects.md`「限流记录的实测台账」。

四层不在 L1–L4 之内，每层的成因、命令与边界全在 `references/out_of_library_layers.md` 对应小节，这里只留判据：
- **用户点名了某一份文件**：先按标题把这一份本身捞出排最前（`tax_terms.title_identity`），不同名不得
  拿同域文件顶位；没定位时按 `cited_state` 分三档说清成因，那是三句不同的话、不得压成一句。
- **专业口径缺口**（`tax_analyze.accounting_gap` 认出「税法借用会计结果」；审计/内控/评估/证券口径按
  题面直接判）：规范逐条原文走 `search_source/maodocs/`，实务答疑与处罚案例走 `search_source/chenyiwei-bbs/`，
  自律规则走 `search_source/szse-lawrules/`。
  【⑦ 第 21 条正文】**禁止用训练数据里的准则记忆补专业口径缺口**：准则与业务规则都在修订，
  接口 `docNo`、URL 里的 t 编号、页面「现行有效」标注都不跟着修订走；缺口只能靠那三个子技能
  实时取，引原文只引「规范名＋条款号」。
- **优惠封闭枚举**：走 `subskills/tax-preference/`，先 `sync` 再离线穷举；给的就是税收依据本体，
  文号取回后**回 ⑧ 定级、可当主依据**。
- **立法过程文件**：判据只看题面用词（`tax_analyze.LEGISLATIVE_STAGES`），不占主依据，草案标明是转述。
- **研发费用加计扣除／高企认定**：另读 `subskills/R&D-Expenses/`——算分、归集与三套口径隔离的领域
  手册，**不是检索源**；它引的政策原文仍回 ③ 取、进 ⑧ 定级。
- **法院判决与复议决定**：司法这一层本仓库未接入，两站的墙 2026-11-25 量过、记在
  `search_source/rmfyalk/` 与 `search_source/wenshu/`。要的是司法裁判口径而库里只有查处通报时，
  答案必须写明这一层缺失（`tax_cases.LIMITATIONS` 那句），**不得**拿通报冒充判决，也不得把
  接口的 `code=401`／`code=9` 说成"库里没有这份文书"（判据 `tax_http.require_court_ok`）。

## ④ 多源聚合：六源都要走

```bash
python scripts/tax_aggregator.py "<关键词>" --size 10
python scripts/tax_aggregator.py "<关键词>" --sources npc,chinatax --size 10  # 仅法规原文层
```

默认六源全开，按权威性排序：NPC → 税务总局 → 搜狗 → 税屋 → 微信公众号 → 中国税网。
【⑦ 第 3 条正文】**禁止单源作答**：④ 的六源必须全走一遍，逐源标明各给了什么、缺了会怎样。
**六个源覆盖的是不同的东西，缺一个就会漏掉答案的那一半**：各源给什么、缺那一路会答不了什么，逐条写在
`references/commands.md`「六源各供什么、缺一路会漏掉哪一半」；聚合后剔除同名不同版本、已被取代、跑题的条目。
**「某一栏全部文件」不在这一步**：整栏横截面用 ⑪ 的政策文件库清单，按词召回凑不出封闭清单，两路不互相顶替。
**依据不足时逐级放宽检索，不是把结论放宽**（更短关键词 → 总局 → 搜狗全网 → 税屋+公众号 → 聚合兜底，整条链
逐档写在 `references/commands.md`「依据不足时放宽的是检索，不是结论」）；六源均无结果就明说未找到，绝不编造。

## ⑤ 各源命令与失败表现

六源的命令全文、参数、NPC 串行闸（`NpcSerialGate` / `TAX_NPC_LOCK_TIMEOUT`）与失败表现对照表在 `references/commands.md`；
③ 末那五路不在六源里，命令写在 `references/out_of_library_layers.md`，它们「没取到」与「取到了但读不得」（编号与
文号都不证明版次）的形态记在所属目录 `SKILL.md`／`NOTE.md`。此处只留五条硬规矩：

- **失败先分诊**：区分"限流"与"代码坏了"——限流等退避重跑，代码问题才改代码。
  把限流误读成接口变更，会去改本来正常的代码。
- **正文取到什么状态只认 `body_status` 这一个键**（值域 `tax_fgk.BODY_STATUSES`：
  `ok`/`dynamic`/`empty`/`error` 四态各是什么、`body_error` 与判定无关、`_attempts` 怎么记账，
  逐条在 `references/source_defects.md`；【⑦ 第 18 条正文】**禁止编造法规库正文**：三种「没拿到」
  都不得据标题推测条文内容，也不得把 `dynamic` 或 `error` 写成「这份文件没有正文」。
- **「这份文件里没有那张表」要说全**：`media_only` 的正文本来就是视频/图片（给 `media_urls`），
  `body_in_attachment` 为真时给附件名与直链——这一格只回答「带没带附件」，要与 `body_status` 一起看。
- **"这一轮 0 条"与"这一轮没取到"分两枚键，一律认键不认文本**：`_zero_hit`＝请求跑成、答案 0 条
  （可以并存一句 `_error` 说明成因），`_fetch_failed`＝请求层面没取到；判据收在
  `tax_http.is_fetch_failure`，六个源与检索层四个消费面同读它；文号核对那一层判的是「能不能据此说库里没有
  这份文件」，有意不同尺，不许顺手统一（理由钉在该函数注释与台账 3.62.27）。`_empty_reason`（翻页越界 vs 这一轮没取到
  清单）与 `_partial_error`（清单取到、逐枚没取全，缺的那几篇单独补读）都不等于「库里没有这份文件」。
  逐源出口形状与两处真缺陷见 `references/source_defects.md`「由代码保证的源缺陷」。
- **临时脚本一律落成 `.py` 文件再执行，跑完删**：heredoc 内嵌 Python 时串里的反斜杠被 shell 折叠掉
  一层，带转义的正则与 Windows 路径因此改坏且不报错——脚本跑得成，产出却是错的。探针的锁、预算与
  记账纪律在 `references/commands.md`「临时脚本与探针的纪律」。

## ⑥ 输出格式模板

模板按 ① 的类型变，**不要所有题都用同一段结构**。九种输出形态（分析六段式、
逐条比对式、填空式、规则陈述式、资格判定条件矩阵式、计算式、依据不足时、风险自检专用、
稽查模拟问询式）的完整模板在 `references/output_templates.md`——每格取什么值、缺格时
怎么写、哪一格由脚本判哪一格由 Agent 判，都以那一份为准，本节不重述。本节只留两样：
做错没人拦得住的禁忌，和四条模块线的触发条件与命令。取舍用的就是 ⑩ 那条准——已由代码
保证的行为不在这儿手写一遍。
共同要求：结论 + 主依据（含文号）+ 其余法定依据 + 执行口径与实务认定 + 限制条件/适用边界分层，附实时时间戳、观察时点与免责声明。
`option_judge` 必须逐条判完每个选项，漏一条比答错更严重——少判的那一条不会报错。立法理由、易混点、救济与期限
三段是**必查项不是可选项**：取到要照原文标出处，取不到写明「未取到」与已经查过的层，不得整段删，也不得用
训练数据的政策记忆来填（⑦ 第 9 条）。
`entitlement` 不得用「满足/不满足」两栏作答：按条件矩阵式走，行判断取
`满足/不满足/未知/不适用` 四值，项结论取 `明确匹配/条件匹配/待资格确认/明确不匹配/
无法判断` 五档——「还缺用户事实」与「还缺认定或备案」是两件事。两项以上候选还要出【候选总览】
与【同享结论】两格；条件矩阵全绿也不等于多项优惠可同享（⑦ 第 22 条）。
`liability` 要出数的那一类不得手算：先跑 `python scripts/tax_calc.py --list` 选骨架，把 ③ 检回的
现行税率、扣除标准、档界逐条连同来源用 `--set`/`--src` 喂进去。引擎里不含任何政策数值，报
`缺参数` 就转 ② 补问；「无来源参数」非空就在答案里点出那一项没出处。
题面有争议、追缴、处罚或「别人这么处理过没有」的资格类比时，先跑一轮类案检索（`python scripts/
tax_cases.py "<主题>" --element <争议要素>`）。类案是**支持层不是法定依据**：它**不占 L1–L4 位次**、
不参与 `pick_primary` 排队，强度上限是「官方处理口径」不是「司法裁判口径」；旧案结论按其发生时的
政策作出，用于本题前要按目标年度重验。
四条模块线在本节只报触发条件、命令与落点，每格取什么值、缺格怎么写都在 `references/output_templates.md` 对应式里：
- **稽查模拟**（对手视角：检查人员会怎么问、对方要哪份材料）：`python scripts/tax_inspect.py --list` 看检查域
  再取问询单元；已有的回答必须用 `--answers` 传进去，一致性核对只取 `一致/矛盾/缺一边/未取数` 四值，做成单边
  写成「一致」脚本不会纠正。落点「稽查模拟问询式」；这一层不预测稽查结果（⑦ 第 11 条）。
- **内控生成**（缺口已盘出、要的是以后不再缺）：`python scripts/tax_control.py --diagnosis gaps.json`
  收上一轮整个输出；一条缺口与假设都不给时拒生成（`tax_control.NeedsDiagnosis`），只要通用模板须
  用 `--assume` 写明假设。落点是六段式的「制度与流程」条件块，不新增输出形态：九格含保存期限，
  缺任一格 `tax_control.validate` 载入时报错；覆盖底线也在载入时判，那两张注册表要一起扩。
- **账套巡检**（账上有结构化行）：先 `python scripts/tax_ledger.py --pending` 取参数工作清单
  交 ③。参数没检回、或检回没给来源的整条不执行记『待核』；判不动的三种成因各有各的动作，
  都不写成「通过」，也不许借邻近档顶位（⑦ 第 26 条）。落点「风险自检专用输出」账套巡检
  条件块，八格与状态值域以那一节为准，不新增第 10 种形态。
- **多合同受理**（一次交来几份合同，或判「合同写的与实际做的是否同一件事」）：先 `python scripts/
  tax_intake.py --blank` 出九维度 × 要素 × 五件套那张表，抽取的每条都要带『文件／位置／摘录』三格出处；
  合同链只到候选，`--confirm <边代号>` 才转已确认、替代边按要素落位，没有『整份失效』判定；对账按
  判断单元逐条比，『无法确认』落成证据缺口三类。落点同一式的多合同受理条件块，不新增第 10 种形态。

## ⑦ 禁止行为清单

编号是这套红线的对外名字，别的文件按「⑦ 第 N 条」引它们，所以**编号一律不动**。清单里只全文放着跨层的
红线；只在某一步里会犯的那些，正文写在**那一步的旁边**（本节下方各步骤的小节，或它所属层的 `references/`
段落），这里留一行指针，指针末尾的 `【⑦ 第 N 条正文】` 就是那一格的锚。搬没搬丢由 `tests/test_doc_contract.py`
的红线归属用例逐条判：整条文字要在登记的位置上逐字出现且只出现一次。

1. **禁止不分析就回答**：必须先判型（`tax_analyze.py`）再检索。
2. **禁止只查上位法就作答**：正文见 ③ 首段的【⑦ 第 2 条正文】。
3. **禁止单源作答**：正文见 ④ 首段的【⑦ 第 3 条正文】。
4. **禁止不判时效就引用法条**：见 ⑧。
5. **禁止猜前提**：题面没交代主体、时点、地区、金额就下具体结论，等于把猜测写成答案。
6. **禁止拿解读顶替被解读的那份文件**：税屋与公众号的文章按角色进"执行口径与
   实务认定"那一栏，照常参与论证，但不得冒充被解读文件的条文；只取到解读、没取到
   原文时，答案要写明原文待核。
7. **禁止用未生效或已废止的依据答当期问题**：正文见
   references/evidence_grading.md「时效判定八条」的【⑦ 第 7 条正文】。
8. **禁止漏判选项**：正文见 references/output_templates.md「逐条比对式」的【⑦ 第 8 条正文】。
9. **禁止使用训练数据的政策信息**：必须以实时 API 返回为准。
10. **禁止代替用户报出应纳税额**：列算式与依据供复核，但不下"你应缴 X 元"的结论，
    标注"以主管税务机关核定为准"。
11. **禁止预测稽查结果**：正文见 references/output_templates.md「稽查模拟问询式」的
    【⑦ 第 11 条正文】。
12. **禁止代替用户做申报操作**：正文见 references/output_templates.md「分析六段式」的
    【⑦ 第 12 条正文】。
13. **禁止引用已废止法规而不标注**：正文见 references/output_templates.md「分析六段式」
    的【⑦ 第 13 条正文】。
14. **禁止省略免责声明**：正文见 references/output_templates.md「分析六段式」的
    【⑦ 第 14 条正文】。
15. **禁止省略查询时间戳与观察时点**：正文见 references/output_templates.md「分析六段式」
    的【⑦ 第 15 条正文】。
16. **禁止忽略 `_reliability` 标记带来的提醒**：正文见 references/evidence_grading.md
    「提醒清单」的【⑦ 第 16 条正文】。
17. **禁止把实务解读当成被解读文件的原文**：正文见
    references/evidence_grading.md「实务材料援引的文号回库核对」的【⑦ 第 17 条正文】。
18. **禁止编造法规库正文**：正文见 ⑤ 硬规矩里的【⑦ 第 18 条正文】。
19. **禁止在未确认计费的情况下调用外部模型**：技能本体六步分析只打公开法规接口，
    一次模型都不调；会花钱的只有 `/api/ai-interpret` 与 `tests/eval_answer.py` 两处，
    扣的是使用者自己配置的模型通道账号额度。闸门在 `scripts/tax_llm.py`，默认关死，
    开启要同时设 `TAX_ENABLE_PAID_LLM=1` 与 `TAX_LLM_CMD=<命令绝对路径>`；批量前先报
    调用次数，上游回额度类错误就停整批——重试只是继续扣钱，并把一次故障写成一片零分。
20. **禁止拿会计准则当税收依据**：准则答的是"会计上怎么确认与计量"，是税法适用的
    前提而非税法规定，只能在【适用边界】或【执行口径与实务认定】栏出现。
21. **禁止用训练数据里的准则记忆补专业口径缺口**：正文见 ③「专业口径缺口」那一格的
    【⑦ 第 21 条正文】。
22. **禁止未查叠加与择一就给出多项优惠可同时享受**：正文见
    references/output_templates.md「资格判定条件矩阵式」的【⑦ 第 22 条正文】。
23. **禁止把择一采用当成矛盾输入的处置**：题面给出的事实互相冲突时，指出冲突并询问，
    不得挑其中一半当既成前提继续算——被回避的那一半往往正是用户真正的情形。
24. **禁止把"这次没查成"写成"库里没有这份文件"**：实务口径援引的文号由
    `check_practice_citations` 回官方库核对（见 ⑧），答案照抄那一条的提醒句。
    `not_in_library`／`not_checked`／`lookup_failed`／`no_body` 四种说的都是本轮没查成
    或没连上，读者的动作是补一轮或换词再查；只有 `repealed` 才可以说那份文件不再执行。
    用 `--no-citation-check` 关掉这一层时，答案里就不许出现"已回库核对"这类话。
25. **禁止把"没有记录"写成"没有发生"**：题面或材料里找不到那一笔、那一份合同、那一次
    履行时，只能说"未提供记录，无法确认"，不得据此下"未发生""无需申报""不涉及该税种"
    这类结论。缺记录是本轮取证的状态，未发生是对事实的认定，两者混写等于把一次没查到
    替读者免除了一项义务。同一纪律在下挖层是待补而不是不适用，在一致性核对里是缺一边
    与未取数两个状态而不是"一致"。这条与第 5 条各管一头：第 5 条禁止拿猜测补前提，
    本条禁止拿空缺当结论。
26. **禁止把巡检里"判不动"的行合并成"通过"**：正文见
    references/output_templates.md「风险自检专用输出」账套巡检条件块的【⑦ 第 26 条正文】。
27. **禁止把未确认的合同链关系当成生效顺序，禁止把没有出处的抽取当成合同原文**：正文见
    references/output_templates.md「风险自检专用输出」多合同受理条件块的【⑦ 第 27 条正文】。

## ⑧ 依据定级：层级、时效、与本题的对应关系，三根轴各判各的

**引用任何法条之前必须先判定它是否有效。** 一条材料身上有三件互相独立的性质，任何一件
都不许折算成另一件，更不许乘成一个「可引用性」之类的合成分（这三根轴各被乘进一个分数时
怎么做错答案，见 `references/evidence_grading.md`「三根轴为什么不能乘成一个分数」）：

| 轴 | 判什么 | 符号 | 能不能否决引用 |
|----|--------|------|----------------|
| 规范层级 | 谁不得抵触谁 | `rank_of` → `LEGAL_RANK` 七档 | **不能**。只在同角色内冲突时用来裁决先后 |
| 时效 | 观察时点上还在不在效 | `judge_validity` | **唯一带后果的一根**：已废止只用于说明沿革，尚未生效不得用于当期 |
| 与本题的对应关系 | 标题或正文里有没有本题的主题词 | `on_topic_of` → True / False / None | **不能**。False 与 None 各换一句提醒，不剔除 |

`LEGAL_RANK` 只装《立法法》确立的那几档，分值是序号不是权重，逐档数值在 `references/evidence_grading.md`
「规范层级表」。技术性口径（`technical`）与实务解读（`interpretation`）是**材料形态不是规范层级**，
不在那张表里，走下面的角色照常进答案并参与论证。

**角色分层（`role_of`）说这条材料在这道题里干什么活**，五档：`direct` 本题的直接规定、`superior` 上位
依据与授权、`practice` 执行口径与实务认定、`history` 政策沿革、`unmatched` 待核对线索；判据按先后走，
次序在 `references/evidence_grading.md`「角色分层与主依据挑选」。标准配置是 `direct` + `superior` +
`practice` 三层都有货；缺哪层就写明缺哪层，不得拿层级高但没规定这件事的文件顶位。

实务层材料的名单只有一份（`tax_evidence.PRACTICE_MARKS`）：官方答复那一批 `rank_of` 归 `technical`、
`role_of` 落 `practice`；两处各列一份名单会漏出相反的错，改前实测反例在「角色分层与主依据挑选」。

**主依据（`pick_primary`）唯一出局的是立法过程件**（人大网草案、审议与征求意见公告，`legislative_process`）
——它不是已公布的条文，这是事实层面的处置不是降权。其余按 `_order_key` 排：能不能直接援引 → 角色 →
时效 → 规范层级 → 主题对应；宪法（`NOT_DIRECTLY_QUOTABLE`）因此永不占头条，仍进上位依据那一层；
`_reliability` 不参与排队，提醒用来源写下的那句、不许自己编原因（⑦ 第 16 条）。出牌顺序与 `medium`
出处在 `references/evidence_grading.md`「宪法不得直接援引」「提醒清单」。

**执行口径要落到一份现行有效的法定文件上（`check_practice_citations`）**：税屋、公众号与官方答复那条
材料本身读不出它援引的公告是否早已废止，这一层把文号拿回税务总局法规库查存在与时效，结果写进
`official_status`（九种取值）；取值分界、四种「本轮没查成」的名字与补发文机关前缀的理由，在
`references/evidence_grading.md`「实务材料援引的文号回库核对」。

时效判定是引用前必做的一步，八条判据的次序与边界在 `references/evidence_grading.md`「时效判定八条」，
这里只留四条会做错答案的：观察时点必须显式 `--at` 传入；「已修改」仍在效但须按修改后的版本引；
**「部分失效/部分废止」含子串「失效」，按整串枚举判为仍在效、不得压成 repealed**；**清单层读不出
执行期限、正文层读得出**（`expiry_of` 取止日、`period_start_of` 取起日，**两端都要与观察时点比过**，
只比止期会把「三天后才开始」判成「在期内」）。越界不改时效档位、只出一条提醒。`tax_answer.py --answer` 会自动定级并分层输出。

**定级后即收口分流（进 ⑥ 前的最后一道闸）**：本轮取到至少一条角色为 `direct` 或 `superior`、且未废止
的法定文件（`tax_answer.compose` 里叫 `statutory`）才进正常六段式；取不到输出 `evidence_gap`，转
`references/output_templates.md`「依据不足时」，只给检索方向、不给数额性结论——这一闸与 ④「六源全空」
是两种不同的空手。`scripts/tax_coverage.py` 判的是「少了哪一类」不是「够不够格」：**没传清单是待核、
传了空清单是缺**，覆盖率不参与收口。两条判据在 `references/evidence_grading.md`「收口判据与覆盖率」。

## ⑨ 税种与专题映射

`tax_search.py` 的 `TAX_TYPE_KEYWORDS` 归类，返回值里的 `authority` 说这一题的依据住在
哪一源，三种取值各走一条查法：

- `"npc"`（有本体法）：按 `parent_law` 做标题精确检索。
- `"sta"`（转让定价、税收协定、税收优惠等，没有本体法）：依据在总局规范性文件里，**必须改查 `tax_fgk.py`**，
  检索词用条目自带的 `search_term`——分类名当检索词多半取不到东西。
- `"overseas"`（全球最低税/支柱二）：中国两个官方库都没有对应文件，按 `sta` 查是 0 条、按 `npc` 查取回标题含
  "企业"二字的无关法律；要查的是关掉文件类标签的总局全站层（`tax_web_search.py "支柱二" --all-labels`），
  专题 `note` 的实测原话照抄进答案；相邻专题各按自己的词另查，踩空边界在 `references/tax_categories.md`「容易踩空的地方」。

三项各几条随表变，别抄数字：`python tests/probe_routing.py --stats` 报 `authority`
分布，往表里加词前后各跑一次 diff 改判条数。
完整映射表、各专题的检索词、容易踩空的边界（消费税没有立法、车购税不在车船税法里、`个税` 会被子串误命中、
跨税种通用词收进某税种会抢走别处整题）全在 `references/tax_categories.md`。
要点：归不出税种时检索词就是用户原话、NPC 按字面匹配标题，`_routed` 会写明这次改查
了什么或"未能归类到税种"，这一句必须读出来。

## ⑬ 质量评测：方法与判据
