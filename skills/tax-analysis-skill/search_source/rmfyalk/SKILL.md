# 人民法院案例库（rmfyalk）——墙在接口层，源未接入

线上：https://rmfyalk.court.gov.cn/ （页面层匿名可达，接口层匿名一律被挡）

本目录是**墙位档案**不是取数器：2026-11-25 首次实测（此前本机一次请求都没发过），
把反爬形状量清并登记；接入这条链没建，`scripts/tax_cases.py` 仍只走税务站内查处通报。

## 什么时候用 / 不用

**用**：用户点名要人民法院案例库的入库案例、裁判要旨；或主线答完税务口径后需要
说明"司法这一层还没取到"。取证前先读本目录 NOTE.md 第二节——它决定了失败必须说成什么。

**不用**：税务行政处罚查处通报与曝光典型（那是 `scripts/tax_cases.py` 已接入的层）；
裁判文书网旧站（墙形不同，见 `search_source/wenshu/`）。

## 工作流

1. **不发请求就能答的**：用户问"库里有没有某案"——按现状直接答"这一层未接入，
   本仓库的类案层只有税务查处通报，强度上限是官方处理口径不是司法裁判口径"
   （`tax_cases.LIMITATIONS` 第二条就是这句话，别改写成"库里没有"）。
2. **要复测墙形的**：手动跑本目录 `probe_rmfyalk_wall.py`（会发真请求，逐发间隔
   2.6 秒），对照 NOTE.md 第二节读数；形状变了就更新
   `references/source_defects.md` 的「仍然是边界的几件事」一节与本目录。
3. **判据**：接口回 HTTP 200 不等于取成。这一族用
   `tax_http.court_business_error`／`tax_http.require_court_ok`（成功值是
   `code=0`），**不许**用 NPC 那把 `tax_http.npc_business_error`（它认 `code=200`，
   会把本库的正常响应拦成失败）。将来接入时客户端必须自己打 `_fetch_failed`。

## 取到之后放哪（给母技能主线看）

现在取不到。将来接入时：司法案例不进母技能的税收效力位阶表打分，落【执行口径与实务
认定】还是【适用边界】按 `tax_cases` 现有 C 档规矩走；被引的**入库案例编号与裁判日期**
必须一起带出，否则读者核不了。

## 两条硬规矩

- **HTTP 200 + `code=401`「未登录」是失败不是空库**。实测六枚接口匿名全部
  200/30 字节回这一句；把它读成"0 条命中"就是把没连上写成没有。
- **补浏览器头不松墙**。UA、Referer、X-Requested-With 都加过，读数一字不差；
  别把"换个头再试"当成重试策略去消耗额度。
