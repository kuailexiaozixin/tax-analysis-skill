# 搜狗站内搜索（scripts/tax_sogou.py）

站点形状、限流读数与判据细节在 `search_source/sogou/NOTE.md`：第一节入口与请求形状，第二节反爬判据与验证码页，第三节闸、预算与熔断，第四节复测入口。

## 工作流

1. **站内限定检索**：`python scripts/tax_sogou.py "关键词" --site chinatax.gov.cn --size 5`。`--site` 是本源的主要用法——不限定站点的时事检索归母技能第④步的多源聚合，不必单独走这里。
2. **直链还原**：结果里给的是搜狗跳转链，`data-url` 那枚才是目标地址；本源只解析出直链，不承诺它一定可达（可达性与正文由取正文那一步判）。
3. **续页**：整页元数据缓存 30 分钟，缓存键不含 size，size 只截输出。翻页式是地址里的 `$N` 段；续页要在缓存过期后重取。
4. **被限流时**：本源会直接报错而不静默少给——熔断冷却期内不发请求，预算用尽时报「本轮没有发请求」。看到这两句不要重跑，把它当"这一路今天到量了"的读数，改走别的源。

## 这一层负责什么、不负责什么

- 负责：限定站点的候选地址、标题、摘要与日期。
- 不负责：权威性判定。搜狗只是目录，命中什么算什么的口径走 `references/evidence_grading.md`；摘要是搜索引擎生成的，不能当引文。
- 与 `search_source/wechat` 的分工：微信公众号那一路走 `weixin.sogou.com`（另一枚入口、另一把闸），本模块走 `m.sogou.com` 网页检索。两把闸不共用，别把一侧的读数搬到另一侧。

## 命令依赖

- `python scripts/tax_sogou.py --help`
- 限流与闸的存废判定读 `references/source_defects.md` 的「限流记录的实测台账」——本模块那两行（桌面历史入口、手机当前入口）是两条不同记录，桌面读数不得移作手机证据。
